### M2 工程决策记录（评估文档允许的工程细节裁量）

1. **授权边界**：R8b 授权只管「后台推进队列」；当前章立即渲染（起播门槛/追上等待）
   是用户当下明确意图，走 RenderService 不受授权限制
2. **引擎切换**：切系统语音 = 释放神经引擎（3GB 机器不养双引擎），回切冷加载 ~5.4s
   在章边界接受；章级单轨播放不依赖引擎就绪（ChapterPlayer 独立轨），切回无感
3. **回切提示**：系统语音播当前章时渲染完成 → Toast 预告 + 下一章边界若已缓存自动切回
   （R9「有提示回切」的落地：提示+边界自然切换，不打断当前句）
4. **暂停语义**：章级单轨 pause = 停轨（续播从当前句重放），与逐句路径语义一致
5. **追上弹窗双通道**：前台 dialog（MainActivity.onResume 捕获 pendingCacheChoice）+
   通知双 action（灭屏兜底），都汇到 ACTION_CHOICE_WAIT/SYSTEM
6. **AAC csd-0 双根因修复**（M1-g 首跑实锤，两轮定位）：
   - 根因一（编码侧）：编码器首个输出 buffer 是 AudioSpecificConfig（CODEC_CONFIG 标志），
     误包 ADTS 头 → 9B 垃圾帧。修复=跳过 csd buffer（还顺带消除了 83 个 7B 空帧）
   - 根因二（解码侧）：**OMX.google.aac.decoder（Android 9 软解）不支持 KEY_IS_ADTS
     in-band 解析**——199 帧良构流 + EOS 喂完仍零输出。修复=解码前从首帧 ADTS 头推导
     csd-0 显式配置 + 喂裸帧（剥 7B 头）。推导公式经逐字节验证：24kHz/mono/LC 的
     0x58 0x40 → ASC 0x13 0x08（与真机编码器 csd 输出吻合）；OMX/Codec2 通吃
   - 兜底：双解码路径 5s 零输出看门狗（wedge → 优雅降级 WAV 而非挂死）

## M2-a AacAdtsStreamDecoder（AacCodec.kt 补流式解码）

- 流式解码 ADTS 流 → 16bit PCM 块回调（`decode(input: InputStream, sr, onPcm16: (ByteArray)->Unit)`）
- 复用 nextAdtsFrame 逻辑改为流上扫帧；direct buffer 纪律同现有代码（禁 array()）
- 用途：章级播放器边解边写 AudioTrack，避免整章 float 载入内存（9 分钟章 ≈ 52MB float 不可接受）

## M2-b ChapterPlayer（playback/ChapterPlayer.kt 新文件）

章级单轨播放：AAC/WAV 缓存 → 一条 AudioTrack 播整章，句边界对位。

- API：
  - `play(key, bookId, chapterIndex, startSentence, callbacks)`：解码流式写入单轨（WRITE_BLOCKING 块写）
  - 句边界：播放头（帧累计）跨 sentenceOffsets[i+1] → `onSentenceEnter(i)`（Service 挂 saveProgress/断点续读）
  - `pause()/resume()`：同轨 pause/play，head 连续（天然支持断点——注意与逐句「每句新轨」教训不冲突：
    那是 head 终身累计破坏 drain 比较；本设计 head 单调累计正是句对位所需）
  - `stop()`、`release()`；跨章由 Service 收 `onChapterDone` 后起下一章
- 从句 N 起 seek：解码跳过前 offsets[N] 帧（不解码直接丢 ADTS 帧更省 CPU——按 ADTS 帧长×1024 帧/帧
  累计跳过，误差 ≤1 帧可接受），轨 head 从 0 起、对位基准 +seekBase
- WAV 降级路径：RandomAccessFile 流式读 float 块写入，对位同构
- 进程被杀恢复：head 对位基准 = 已写帧数（write 成功即推进），句判定容差 ±2048 帧

## M2-c RenderService（service/RenderService.kt 新文件，R8a 前台渲染服务）

- 前台服务（FGS），通知「《书名》缓存中 第x章（已缓存 n）」IMPORTANCE_LOW，点击回 MainActivity
- 通知 action：停止渲染
- 队列语义「当前章优先→后续章」：输入 (bookId, fromChapter)，逐章 renderChapter()，章间查停止位
- 完成单章发 LocalBroadcast（进度/追上「缓存已跟上」信号）
- 与播放并存：读 ModelManager 就绪态；渲染失败（模型忙/编码降级）不重试（M1 幂等语义保留）
- Android 14 FGS 类型：mediaPlayback 不适用——渲染服务用 dataSync? （targetSdk 34 起 FGS 需声明类型；
  渲染是计算+磁盘，非媒体播放。用 `dataSync` 并在 manifest 声明；CI 真机构建已过 16KB 对齐核查，
  API 34 FGS type 声明补 manifest 即可）

## M2-d RenderPrefs + R8b 授权映射

- RenderPrefs（存 SharedPreferences）：`renderAuth` ∈ {unasked, battery, charging}
- 映射：
  - battery → 播放中后台渲染走 RenderService（随时跑）
  - charging → 保留 WorkManager charging 约束（现有 PrerenderWorker，改为从当前章起排）
  - unasked → 首次触发后台渲染时 MainActivity 弹授权 dialog（两选项+记住），弹窗天然前台（播放入口）
- M2 只做简单授权 dialog；M3 向导把它作为一步复用（不重复实现状态机）

## M2-e ReadAloudService 改造

1. **起播门槛**（R9「先缓存第 1-3 章→先听」）：
   - 点书 → 查当前章缓存：命中 → 直接起播（后续章按授权映射后台渲）
   - 未命中 → 启动 RenderService 从当前章渲（通知进度），**渲满 min(3, 总章数) 章或当前章+2 章**
     完成后起播；渲染期间通知栏可见进度
   - 慢机等待时长告知：通知文案带「约 x 分钟/章」（StorageEstimator 反推时长）
2. **播放判定（永不现场合成原则的 UX 层落实）**：
   - playCurrent 改为章级判定：当前章缓存命中 → ChapterPlayer 整章播（句回调照旧驱动进度）
   - 未命中 → 追上流程（不再走 engine.speak 现场合成——engine 兜底保留仅作 race 防线）
3. **追上检测**（章边界触发：onChapterDone 时下一章未缓存）：
   - RenderService 正在渲该书下一章 → 自动「暂停等缓存」（暂停+Toast 等待，缓存完成自动续播）
   - 否则弹二选一（MainActivity 前台时 dialog；不在前台时通知栏两 action）：
     - 「暂停等缓存」→ 排渲 + 暂停，完成自动续
     - 「切系统语音」→ 引擎运行时切换到 SystemReadAloudEngine 继续播（从当前句），边播边渲；
       缓存追上（当前章渲完）→ 通知提示可切回（点通知 action 切回，不打断当前句）
   - 会话内记住选择（R3 风险表：慢机频繁打扰对策）
4. **引擎切换**：`switchEngine(newEngine)`——停当前句 → 换引擎 → 从当前句续播；MediaSession/通知保持
