# EarBook 真机测试报告 — 2026-10-06（Mi Note 3 / Android 9 / MIUI 10）

测试对象：app-debug.apk（M3 构建后追加两处真机修复，见「修复」节）
测试机：Mi Note 3（Android 9 / API 28，arm64，已 root、已瘦身）

## 结论

**安卓 9 真机全链路打通**：导入 TXT → sherpa 模型加载 → 句级合成 → AudioTrack 24kHz 出声 → 媒体通知（transport 3 按钮，「第一章 起点」）。
**安卓 11 兼容性静态审计全绿**（详见下表），无需改动即可跑；模拟器实测因沙箱磁盘不足未做（需 ~7.4G 空闲，现有 2.3G）。

## 修复 diff（未提交，待开发会话拍板）

1. `ReadAloudService.kt`：选 sherpa 引擎后 `.also { it.ensureModelLoadedAsync() }`
2. `SherpaReadAloudEngine.kt`：speak 冷启动窗口 `waitForCore(30s)` 有界等待（模型冷加载 5.4s 实测），不再秒败
3. `SherpaReadAloudEngine.kt`：线程优先级改 `Process.setThreadPriority(tid, URGENT_AUDIO)`（init/prefetch 线程的 `BACKGROUND=10` 在合法范围内不炸，但语义也是错的，建议一并统一）

## 最新系统兼容（API 26→36 全区间，2026-10-06 追加核查）

**结论：Android 14/15/16 均可运行，无需改动。** 证据：

| 新系统专属雷 | 核查结果 |
|---|---|
| 前台服务新权限（Android 14+ 设备对 targetSdk 34 强制） | `FOREGROUND_SERVICE_MEDIA_PLAYBACK` 已声明（ELF/manifest 实查）✓ |
| **16KB 内存页对齐**（2025+ 新硬件，原生库不满足即闪退） | readelf 实测：`libsherpa-onnx-jni.so` + `libonnxruntime.so` LOAD 段全 0x4000 对齐 ✓ |
| 通知运行时权限（API 33+ 设备） | 代码已有 SDK 33 分支申请 ✓ |
| FGS 超时（Android 15 的 6h 限只针对 dataSync 类） | mediaPlayback 不受限 ✓ |
| 强制 edge-to-edge / 手势返回（15/16 对 target 35/36+ 才强制） | target 34 不受影响 ✓ |

非阻塞提醒：将来上 Google Play 需升 target 35+（届时适配 edge-to-edge）；个别新 ROM 对侧载 app 权限弹窗保守，通知授权可能需手动去设置开。

安卓 11 结论：**无需任何改动即可运行**。今天修的 F3/F4 均为版本无关缺陷（在 11 上同样会触发，修复同样生效）。

## 附注

- 沙箱 JDK 残缺：`/usr/lib/jvm/java-21` 只有 4 个工具（无 jlink/javac），完整 JDK 在 `/home/z/jdk-local/...`，构建需 `JAVA_HOME` 指过去
